# 运营问数 Agent

> 用中文提问 → **大模型把它翻译成结构化查询** → 本地执行 → **大模型写出结论** → 出图并可导出 Excel。
> **没有任何预置答案**：每个问题都真的调用大模型，本地只负责约束、执行和渲染。

---

## 怎么打开

| 文件 | 用途 | 是否提交到仓库 |
|---|---|---|
| **`问数Agent_本机演示.html`** | **本机演示用**，已内嵌 API Key，双击即用 | ❌ **不提交**（在 .gitignore 里） |
| `问数Agent.html` | 给别人看的版本，**不含任何 Key**，双击后自己填 | ✅ 提交 |

两个文件都必须先由构建脚本生成：

```powershell
python agent/src/build_agent.py
```

> ⚠️ **为什么必须分成两个文件**
> API Key 一旦进了公开仓库，几分钟内就会被爬虫扫走盗用。
> 所以「本机演示用」和「可以给别人看」在物理上就是两个文件——
> 构建脚本读项目根的 `.env`（已 gitignore）来注入 Key，**公开版注入的是空字符串**。

## 它是怎么工作的

```
你的中文问题
   ↓
① 理解问题        把「数据字典 + 问题」交给大模型（本地不做任何判断）
   ↓
② 生成查询        大模型输出一个结构化查询 JSON（不是代码、也不是答案）
   ↓
③ 口径守卫        本地硬规则：按项目纪律收紧标签层
   ↓
④ 本地执行        在浏览器里对已内嵌的 4,375 条数据跑查询，数据不出本机
   ↓
⑤ 写结论          把结果表喂回大模型，让它写 120~220 字的解读
   ↓
⑥ 渲染与导出      指标卡 + 内联 SVG 图 + 标签页 + 下载 Excel 工作簿
```

**每次提问 = 2 次大模型调用**（生成查询、写结论），实测单次约 2~3 秒。

### 三个设计上的关键决定

**1）大模型只能输出「结构化查询」，不能写代码、不能直接给数字**

查询的字段、指标、分组维度、图表类型**全部走白名单**：

- 分组维度：`label / pline / cat / brands / pains / scenes / fmt / kw / year / official / duration_bin / tier`
- 指标：`count / play_median / play_mean / interact_mean / fav_rate_mean / like_median / dm_per_1k / creators / official_share`
- 筛选字段：`label / pline / cat / brands / pains / scenes / fmt / kw / official / year_min / year_max / duration_min / duration_max / play_min / title_contains`

模型给出的任何白名单之外的字段都会被**本地剥离并记入「口径守卫」**。
这样就从结构上排除了**提示词注入**和**数值幻觉**——所有数字都是本地算出来的。

**2）「口径守卫」是本项目独有的业务纪律，而且是本地硬规则**

项目里有一条分析纪律，Agent 用**代码**落实，不指望模型自觉：

| 分组维度 | 允许的标签层 | 理由 |
|---|---|---|
| 产品线 / 品牌 | **只用 A 级** | C 级的萌宠日常不是产品讨论，混进来结论就失真 |
| 痛点 / 场景 | **A + B + C** | 需求既来自产品吐槽，也来自耗材与养护语境；剔除 N 级（非宠物） |
| 内容形态 / 时长 / 创作者分层 | **A + B** | 内容策略针对硬件本体与耗材日用 |

每次运行都会显示「守卫动作」，并写进导出的 Excel。

**3）规则优先不再存在——所有判断都交给大模型**

上一版有 15 个预定义操作 + 12 个预置答案。这一版**全部删掉**：
没有预置问题、没有缓存答案，模型每次现算要查什么。
换来的是覆盖面（问法不受限）和真实感（真的是 Agent 在工作）。

## 导出的 Excel 长什么样

| 工作表 | 内容 |
|---|---|
| **说明与数据性质**（第 1 张） | 问题 / 生成时间 / 数据规模 / 大模型意图 / 命中条数 / 分组维度 / 最终标签层<br>⚠ 数据性质声明：抽样方式、标注质量、已知噪声、口径纪律、标签层含义<br>口径守卫本次的每一条调整 |
| **AI 解读** | 大模型写的结论文本 |
| **查询与口径** | 本次的结构化查询 JSON 原文 + 口径调整记录 |
| **结果表** | 分组结果；百分比与千分位是**带数字格式的真数字**，可在 Excel 里排序筛选 |

**第 1 张永远是「说明与数据性质」**——任何人拿到文件都先看到"哪些能用、哪些不能"。

## 已知局限

1. **依赖外网**：每次提问都要调用 DeepSeek，网络不通就用不了（会明确报错，不会假装有结果）。
2. **每次提问有 API 成本**：约 2 次调用 / 问题。
3. **模型可能选错分组维度**：它有时会把"产品线"理解成"词典产品线"（`cat`）而不是"大模型判定"（`pline`）。结果表会显示实际用了哪个，口径守卫也会兜住标签层，但维度本身要自己看一眼。
4. **数据本身的口径局限**（关键词搜索、非随机抽样、标注准确率 88.0%）
   在页面底部与 Excel 第 1 张都有完整声明。
