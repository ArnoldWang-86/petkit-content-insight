# 运营问数 Agent

> 用中文提问，Agent 自己完成「意图识别 → 操作选择 → 口径守卫 → 浏览器内计算 → 出图」，
> 你直接拿走结论和明细数据。**单文件、离线可用、不依赖后端。**

---

## 怎么打开

**双击 `运营问数Agent.html`** 就行。它是一个 **1.8 MB** 的单文件，
数据（4,375 条内容）、Excel 生成库、全部逻辑都已经内嵌进去，**断网也能跑**。

> **结果形式**：指标卡 → 内联 SVG 图 → 标签页（结果解读 / 明细表 / 说明与数据性质）
> → Agent 解读 → **一键下载 Excel**。
> 导出的工作簿**第 1 张永远是「说明与数据性质」**（抽样方式、标注质量、已知噪声、口径纪律），
> 后面才是结果解读与全部明细表——这样任何人拿到文件都能看懂"哪些能用、哪些不能"。

---

## 怎么用

在输入框里用中文提问，或者点下面的示例问题。比如：

| 你可以这样问 | Agent 会做的事 |
|---|---|
| 哪条产品线的内容互动率最高？ | 按 A 级记录统计各产品线互动率并排序 |
| 小佩和竞品的官方内容差在哪？ | 对比官方账号与达人/用户内容的效率 |
| 哪个痛点播放量高但内容还不多？ | 出「内容量 × 播放中位数」散点，找机会点 |
| 视频做多长效果更好 | 按 <1min / 1-3 / 3-10 / >10min 分档对比 |
| 猫砂盆有多少条内容 | 按条件计数并给明细 |
| 小佩和霍曼哪个互动更好 | 两品牌逐项对比 |

**可选**：在页面上填入 DeepSeek API Key，规则匹配不上的问题会交给大模型做**意图识别**
（只做路由，不回答业务问题本身）。不填也能用——**12 个预置问题不依赖网络**。

## 它是怎么做出来的（架构）

```
你的问题
   ↓
① 意图识别        规则打分匹配（关键词 + 实体加权）；命中不了才调大模型做路由
   ↓
② 操作选择        白名单校验：只能从 15 个预定义操作里选，参数逐项校验
   ↓
③ 口径守卫        按业务纪律过滤标签层（这是本项目独有的规则）
   ↓
④ 执行引擎        全部在你的浏览器里算，数据不上传
   ↓
⑤ 结果组装        指标卡 + 图 + 明细表 + 一句话结论
   ↓
⑥ 渲染与导出      可下载 CSV，用 Excel 直接打开
```

### 三个设计上的关键决定

**1）不让模型自由写 SQL / pandas 代码，改成「白名单操作」**

Agent 只能从 15 个预定义操作里挑一个、填参数，参数还会被逐项校验
（枚举值、品牌表、数值范围）。这从结构上排除了「模型幻觉出一个错误查询」
和「提示词注入」两类风险。

**2）「口径守卫」这一层是本项目独有的**

项目里有一条分析纪律：**产品线与品牌结论只能用 A 级（智能硬件本体）记录**，
痛点/场景用 A+B+C，内容形态/时长用 A+B。

Agent 把这条纪律写进了执行路径里 —— 每次运行都会显示
「进入计算 N 条 / 被纪律剔除 M 条」，并说明为什么。
所以它**不会**把「萌宠日常」混进产品结论里。

**3）规则优先、大模型兜底**

规则路径**完全离线**，响应在毫秒级，而且行为可预测；
只有规则确实匹配不上的问题才交给大模型。
这也是为什么页面上写着「不填 Key 也能用」。

## 评测：它到底有多准

不做评测的 demo 只能「看起来能跑」。所以我准备了一组业务问题当测试集：

```powershell
node agent/eval/eval_agent.js
```

结果（**离线规则路径**，不调大模型）：

| 指标 | 结果 |
|---|---|
| 意图识别准确率 | **27/28 = 96.4%** |
| 参数抽取准确率 | **28/28 = 100.0%** |
| 端到端正确率 | **27/28 = 96.4%** |

唯一失败的一条是「横评类内容的表现如何」——它同时包含
「横评」（属于品牌份额的关键词）和「内容形态」两层意思，**问句本身有歧义**。
这种歧义正是需要大模型兜底的场景，我没有为了跑分好看去硬调它。

> 测试集在 `agent/eval/questions.json`，你可以自己改/加。

### 端到端自检（把整条链路真的跑一遍）

```powershell
node agent/eval/e2e_check.js            # 只测离线路径
node agent/eval/e2e_check.js --with-llm # 额外测大模型兜底
```

实测：离线 5/5 通过；含大模型 7/7 通过（含一条"超出范围"的问题被**正确拒绝**）。

### 三个健壮性设计（都是踩过坑之后补的）

| 问题 | 处理 |
|---|---|
| **大模型请求可能一直挂着**（网络/代理不通时 fetch 不返回） | 加 **15 秒超时**；超时或失败**自动回退到规则匹配**，绝不把界面卡在"运行中" |
| **问题超出数据范围**（比如问营收、问时间序列） | 让大模型可以明确返回 `none`，页面直接说明**「这个问题超出了数据集范围」**，并列出它**能**回答的问题类型——**宁可拒答，不编答案** |
| **页面出现未捕获的脚本错误** | 顶部加了一条**错误横幅**，任何未捕获的异常/异步错误都会直接显示出来，不会"点了没反应" |

## 现场演示的讲法（建议顺序）

1. **先打开看板** —— `https://arnoldwang-86.github.io/petkit-content-insight/`
   一句话交代："这是从 4,375 条 B站 内容里跑出来的五路洞察。"
2. **再打开这个 Agent** —— 双击 HTML，问一句：
   > 「**小佩和竞品的官方内容差在哪？**」
   然后指着左边的流程图讲："它先做意图识别，**只从白名单里选操作**，
   再过一层**口径守卫**——产品线结论只用 A 级记录，最后在浏览器里算完。"
3. **追一个"机会点"问题** —— 问「**哪个痛点播放量高但内容还不多？**」
   指着散点图的左上方说："这些是播放高、供给少的痛点，就是内容机会点。"
4. **收口** ——
   > "这个 Agent 不是重点，重点是它背后那套标注：19 条可弃权规则 + 大模型主判 +
   > 自一致性投票，再用 300 条人工抽检验证，主口径准确率 88.0%。
   > 而且我**量化了人工标注自身的噪声**——二轮盲判复核发现我自己只有 38.2% 的自洽率，
   > 所以我给的准确率是一个区间，不是一个数字。"

## 文件说明

| 文件 | 说明 |
|---|---|
| `运营问数Agent.html` | ★ 交付物（单文件，双击即用） |
| `tools/xlsx.full.min.js` | SheetJS，用于在浏览器里生成 .xlsx（内嵌进 HTML） |

| `src/build_agent.py` | 组装脚本：把数据与图表库内联进模板 |
| `eval/questions.json` | 28 条业务问题测试集 |
| `eval/eval_agent.js` | 路由与参数抽取的准确率评测 |
| `eval/e2e_check.js` | 端到端自检（含 Excel 工作簿结构校验） |

重新生成：

```powershell
python agent/src/build_agent.py     # 重新组装 HTML
node   agent/eval/eval_agent.js     # 重新评测
```

## 已知局限

1. **规则路径有词表依赖**：问法换一种说法可能就匹配不上，这时需要大模型兜底（或补关键词）。
2. **只有 15 个预定义操作**：超出范围的问题（比如"上周涨了多少"）没有对应操作，因为
   本项目的数据没有时间序列。
3. **大模型只做路由，不回答问题**：所有数字都由本地操作算出，模型不参与数值生成——
   这是刻意的设计，避免模型编数字。
4. **数据本身的口径局限**（关键词搜索、非随机抽样、标注准确率 88.0%）
   在页面底部有完整声明，Agent 的每个结论都带着这条声明。
