## 二、方法逐个说明

### 方法1：标注函数（Labeling Functions, LF）

**正确用法**（来源：A Survey on Programmatic Weak Supervision, arXiv:2202.05433 全文）

LF 的正式定义：

    λ : X → Y ∪ {-1}

即每个 LF 对一条数据要么给出一个类别标签，要么**弃权（-1）**。
LF 是「有噪声、错误率各不相同」的投票者，多条 LF 会 **overlap（重叠）** 和 **conflict（冲突）**。

**我们现有实现的问题**：
- `rule_signal()` 对每条记录都强制给出判定，**从不弃权** —— 违反 LF 定义
- 只统计每条规则「命中多少次」，**从不评估规则自身的精度** —— 而 LF 的核心就是「错误率各不相同」
- 用 if-else 优先级链决定结果，**不是投票聚合**

**我们的适配**：
1. 改成 **per-LF 投票**：每条规则对每条数据输出 类别 或 弃权
2. 记录每条 LF 的 **coverage（覆盖率 = 非弃权比例）** 与 **accuracy（在人工标注子集上的精度）**
3. 聚合交给「加权投票」或 label model（见方法3）

### 方法2：数据编程 / 标签模型（Data Programming, Snorkel）

**正确用法**（来源：Snorkel: Rapid Training Data Creation with Weak Supervision, arXiv:1711.10160 全文）

核心机制：把每条 LF 建模为**带噪投票者**，在**没有真实标签**的情况下估计各 LF 的精度，
生成概率化训练标签。原文关键点：

- 两个挑战：① 来源会重叠冲突，需在无真值下估计精度；② 要把标签质量信息传给下游模型
- **不加权的多数投票会失效** —— 原文 Example 1.1：高精度低覆盖的来源 vs 低精度高覆盖的来源冲突时，
  不加权投票直接产生平票（null label）；正确做法是**按估计出的精度加权，冲突时听高精度那条**
- 但要注意 **相互独立的假设**：若两条 LF 表达相似启发式，会「重复计数」，需要建模依赖

**最关键的一条（决定我们该不该用它）**：

原文提出 **Modeling Advantage（建模优势）** 来衡量「加权投票相对不加权投票的提升」，
并在真实数据集上实测：

| 数据集 | 建模优势 A_w |
|---|---|
| Radiology | 7.0% |
| CDR | 4.9% |
| Spouses | 4.4% |
| Chem | **0.1%** |
| EHR | 2.8% |

并且原文提出一个 **低密度上界**：建模优势期望以 **O(d̄²)** 增长（d̄ = 标签密度）。
**当标签密度低时，加权投票就够了，不需要完整生成模型。**
原文甚至写了一个优化器，**自动决定何时直接用多数投票、跳过精度建模**。

**我们的适配（重要结论）**：
- 我们只有 6 条规则、4 个类别，**标签密度低**
- 按上述理论，**引入完整 label model 属于过度工程**
- **应采用「按实测精度加权的多数投票」**，这也是 Snorkel 自己对低密度场景的建议

### 方法3：ULF 标注函数纠错

**正确用法**（来源：ULF: Unsupervised Labeling Function Correction using Cross-Validation, arXiv:2204.06863 全文）

真实机制（**不是我之前以为的「需要人工标签」**）：

1. 用 k-fold 交叉验证，轮流「留出」一部分 LF
2. 用其余 LF 训练一个**下游分类器**
3. 用该分类器在留出样本上的预测，去识别被留出 LF 的**偏置**
4. 据此**修正「LF → 类别」的分配**（refines the allocation of LFs to classes）

**它的前提条件**（原文实验设置）：
- 需要一个**真实的下游分类器**（原文用逻辑回归 / 微调预训练模型）
- 原文数据集有 **15~30 条 LF**（YouTube spam、Spouse 关系抽取等）
- 任务形态是**多 LF 对同一条数据投票**

**我们的适配（结论：不采用完整 ULF）**：
- 我们只有 **6 条规则**，远少于原文的 15~30 条
- 我们**不训练下游分类器**，最终产物是「给人看的分析结论」，不是模型
- **因此完整 ULF 不适用**。但**借鉴其思想**：用「模型/人工的信号」去校验每条规则是否可信
- 具体落地：**用人工抽检子集直接测量每条规则的精度**，低精度规则降权或删除

> 这一条修正了我之前的两个错误说法：① 曾说 ULF「需要人工标签」（错，它不需要）；
> ② 曾把它列为必做项（错，我们场景不适用）。

### 方法4：大模型标注 + 自一致性投票

**正确用法**（来源：LLM for Data Annotation and Synthesis: A Survey, arXiv:2402.13446；
Self-Consistency, arXiv:2203.11171）

- LLM 标注需要**专门的评估环节**（该综述专门有一节 "LLM-Generated Annotations Assessment"）
- 自一致性：对同一输入**多次采样**，取**多数答案**，可显著提升稳定性
- **用投票一致率作为置信度，比让模型自报置信度更可靠**（模型自报普遍过度自信）

**我们的适配**：
- 已实现：temperature=0 主判 + 低置信样本 3 次采样投票
- **改进点**：把「自报 confidence」与「投票一致率」**同时记录**，用人工抽检看哪个与实际正确率更相关

### 方法5：人工抽检与置信区间

**正确用法**：
- 要估计总体准确率，必须用**随机（或分层随机）抽样**，否则有选择偏差
- 小样本比例估计用 **Wilson 区间**（优于正态近似，尤其在比例接近 0/1 或样本量小时）
- 来源：Reliable Programmatic Weak Supervision with Confidence Intervals, arXiv:2508.03896

**我们之前的错误（已确认）**：
- 我曾建议「用主动学习挑的样本去算准确率」—— **这会产生选择偏差，准确率数字无效**
- 正确分工：**随机抽样用于度量，主动学习用于发现错误**

**样本量对比**（假设真实准确率 90%）：

| 方案 | 总人工 | 整体 95%CI | 能否公布准确率 | 错误发现效率 |
|---|---|---|---|---|
| 纯主动学习 200 | 200 | 不可计算 | ❌ 选择偏差 | 高 |
| 纯随机 200（分层） | 200 | 85.1%~93.4% | ✅ 单层 ±8.5pp | 中 |
| **随机 200 + 主动 100（已选）** | **300** | **85.1%~93.4%** | ✅ 单层 ±8.5pp | **高** |
| 随机 300 + 主动 100 | 400 | 86.1%~92.9% | ✅ 单层 ±7.1pp | 高 |
| 纯随机 400 | 400 | 86.7%~92.6% | ✅ 单层 ±6pp | 中 |

**为什么不能「纯主动」**：主动学习刻意挑选最不确定的样本，其错误率**必然偏高**。
用它计算准确率不是「有误差」而是**系统性错误**，因此纯主动方案无法产出可公布的准确率。

**为什么不能「纯随机」**：文献共识（arXiv:2009.00236）是不确定性采样的**单位人工错误发现效率
是随机采样的 2~5 倍**。纯随机虽然能算准确率，但发现错误模式效率偏低，不利于改规则。

**最终采用：随机 200 + 主动 100（共 300 条）**，两者兼得，仅多付 100 条人工。

#### 抽检样本的具体分配

| 用途 | 抽样方式 | 数量 | 回答的问题 | 是否用于度量 |
|---|---|---|---|---|
| **度量** | **分层随机** | 200 | 模型整体准确率是多少 | ✅ 是 |
| **改进** | **主动学习** | 100 | 我错在哪、哪条规则不可靠 | ❌ 否（仅用于改规则） |

分层随机的 200 条，按相关性级别分配：

| 层级 | 抽样量 | 理由 |
|---|---|---|
| A 直接相关 | 80 | 结论主体，错不起 |
| B 延伸相关 | 40 | 影响产品决策 |
| C 用户语境 | 60 | 数量占比大 |
| N 噪声 | 20 | 错误模式已较明确 |

（按 A/B/C/N 在总体中的占比做了近似比例分配，并适当向 A 层倾斜。）

### 方法6：主动学习

**正确用法**（来源：A Survey of Deep Active Learning, arXiv:2009.00236；
A Survey on Programmatic Weak Supervision 第7节）

主动学习有两种粒度：
- **实例级**：挑数据点给人标注
- **函数级**：挑**有缺陷的 LF** 请专家修正 —— 综述指出这种方式**标注成本更低、性能更好**

**我们的适配**：
- 实例级用于**发现错误模式**
- 函数级用于**决定哪条规则该改**（这正是我们需要的）

## 三、据此确定的最终方案

| 层 | 做法 | 依据 |
|---|---|---|
| ① 规则层 | 每条规则可**弃权**；统计 coverage 与 accuracy | LF 定义（2202.05433） |
| ② 聚合层 | **按实测精度加权的多数投票**（不用完整 label model） | Snorkel 低密度上界（1711.10160） |
| ③ LLM 层 | temperature=0 主判 + 低置信样本自一致性投票 | 2203.11171 / 2402.13446 |
| ④ 验证层 | **分层随机 200 条**算准确率 + Wilson 区间 | 2508.03896 |
| ⑤ 改进层 | **主动学习 100 条**找错误，用于改规则（不用于度量） | 2406.12114 / 2009.00236 |
| ⑥ 规则评估 | 用人工子集直接测每条规则精度，低精度降权/删 | 借鉴 ULF 思想（2204.06863） |

**明确不做的**：
- ❌ 完整 Snorkel label model —— 低标签密度下收益极小（原文实测最低仅 0.1%）
- ❌ 完整 ULF —— 我们只有 6 条规则且无下游分类器，不满足其前提
- ❌ SetFit 少样本微调 —— 几千条样本的规模下，用大模型直接标注更简单有效

## 六、v2 修订记录（2026-10-06，全流程跑通后按**实测结果**修订）

> 本节的每一条都由实测数据触发，不是主观调整。
> 原始数字见 `results/人工抽检_300条_方案B.csv`、`results/规则精度.json`、`results/analysis.json`。

### 修订1：最终标签改为「大模型主判」，规则层降级为可解释性报告

在 **200 条分层随机抽检（无偏度量集）** 上对比 5 种方案（下表是**补采前 3,747 条**时的实测）：

| 口径 | 准确率 |
|---|---|
| **只用大模型（主判 + 自一致性投票）** | **89.5%** |
| 默认先验权重聚合（规则 + 大模型） | 87.5% |
| 用 100 条主动样本校准权重后聚合 | 81.0% |
| 只保留精度 ≥80% 的规则再聚合 | 89.0% |
| 修掉子串 bug 后，默认权重聚合 | 89.5%（与只用大模型打平） |

补采到 4,375 条后复测，**结论不变：只用大模型 88.0% / 规则聚合 88.5%**，仍然是打平。

McNemar 配对检验：随机 200 上 p = 1.000（完全打平），全部 300 上 p = 0.523。

**结论**：在本数据集（19 条规则、4 个类别、低标签密度）上，规则层的加权聚合
**不能提升最终标签质量**。故 `final_label` 取大模型判定，规则层的独立投票结果保留在
`agg_label` 字段，作为「可解释性 + 覆盖度」报告与错误分析的依据。
这与项目既定决策「LLM 主判，规则辅助」一致。

> 这也修正了本文档原第二节的一处推断：原文按 Snorkel 的「低密度上界」认为
> **加权投票即可**；实测进一步表明，低密度场景下更好的是**直接采用高精度来源（大模型）**。

### 修订2：规则层必须做「子串陷阱」防护

实测（补采前全量 3,747 条）：耗材规则 `LF_SUPPLY` 投出 878 票，其中 **514 票（59%）**
是把「猫砂盆」里的「猫砂」当成了耗材证据。

| 指标 | 修复前 | 修复后 |
|---|---|---|
| LF_SUPPLY 投票数 | 878 | 179 |
| 「猫砂盆」造成的假阳性 | 514 | 28 |
| LF_SUPPLY 实测精度 | 14.9% | 30%～40% |
| 规则聚合准确率（随机 200，补采前） | 87.5% | 89.5% |

实现：`classifier.SUBSTRING_GUARDS` —— 若短词的每一次出现都被某个长词包住，就不算它独立出现。
同时修复「玩具」（假阳性 83%）与「熊猫 / 猫眼」里的「猫」。

### 修订3：标签是噪声源，耗材类规则只看标题

实测：猫视频的标签里普遍挂着「狗粮 / 遛狗 / 养狗」这类通用词，
抽检中 `LF_SUPPLY` 因标签命中「狗粮」的样本 **6/6 全是假阳性**。
故 `LF_SUPPLY` 改为只在**标题**里找证据（精度 27% → 40%）。

### 修订4：健康医疗归 C（并同步修正速查卡）

`人工核对速查卡` 第一版把「健康医疗」列在 B 之下，与 `标签体系修订记录v2` 冲突，
导致人工抽检中 5 条按旧标准判成了 B。现已把速查卡（md + docx）同步为 **健康医疗 → C**，
并在判断原则里新增一条。

### 修订5：不要用极小的主动样本校准权重

`aggregator.calibrate_weights` 只在 100 条主动样本上估计精度，
`LF_A_BRAND_HW` 恰好只投了 1 票 → 精度算成 0% → 权重从 1.6 被砍到 0.4
（而它在 300 条上的真实精度是 91.2%）。结果校准后准确率掉到 81.0%。
**故 step5 不再自动写 `rule_weights.json`**，权重校准留给下一轮、且必须在独立样本上做。

### 修订6：评估口径升级为「主口径 + 后分层加权 + 人工噪声」

- **主口径**：`final_label` vs 一轮人工，**只用随机 200 条**（无偏、可公布）
- **后分层加权**：按 `final_label` 分层、权重取全量分布
  （补采前 88.9% vs 朴素 89.5%；补采后 87.3% vs 88.0%，两次都只差 0.6~0.7pp）
- **人工噪声分析**（新增）：对 34 条「模型与人工分歧」条目做**二轮盲判复核**
  → 人工自洽率仅 **38.2%**，其中 16 条改判成与模型一致
  → 真实准确率区间 **[88.0%, 93.5%]**（补采前为 [89.5%, 94.5%]），公开采用保守值 **88.0%**
  → 该方法学价值：**量化了"金标准本身的噪声"**，这是多数作品集做不到的
- **规则精度**：同时给出「全 300 条」与「仅随机 200 条」两列（后者无分层偏差）

### 修订7：补采——被限流中断却"静默跳过"的数据缺口

核对页码时发现：35 个关键词里 **22 个采满 10 页，13 个提前停止**。
查代码后发现，**两种**情况都会让采集脚本停下：

```js
if (res === null) { ...; break; }   // ① 连续 6 次请求失败（被限流 -412）
if (!res.length) break;             // ② 这一页真的没结果
```

**而当时没有记录是哪一种。** 于是拿这 13 个词"当年停住那一页的下一页"在线复测：
5 个仍能返回 20 条 → 证实当年是被限流退出的，数据确实漏了。

**处置**：把这 13 个词从完成列表移出、限速从 0.9 秒放宽到 3 秒重采。

| 指标 | 补采前 | 补采后 |
|---|---|---|
| 原始数据 | 6,592 行 | **8,792 行** |
| 唯一视频 | 4,800 | **5,756** |
| 有效样本 | 3,747 | **4,375** |
| 独立创作者 | 2,658 | **3,039** |

**关键校验**：清洗后确认**前 3,747 条的行序与内容 0 变化**，
所以旧的人工标注、旧标签全部继续可用。
另外写了 `src/py/migrate_ckpt.py` 迁移检查点，
只补标尾部 26 批（约 650 条 / 9.6 万 tokens），而不是全量重标（约 59 万 tokens）。

> **教训**：采集脚本必须记录"为什么停"，否则你无法区分"采完了"和"被拦了"。

### 修订8：自一致性投票有 ±1.5pp 的方法方差

补采后重跑投票（同一批数据、同一流程），随机 200 条的准确率
**从 89.5% 变成 88.0%**。逐条比对后确认：差异**全部来自投票这一步的随机性**——
升温采样（temperature=0.8）每次抽的不一样，3,747 条里有 **63 条（1.7%）**因此改了标签。

这不是数据质量问题，是**方法本身的方差**。处置：
- 公开材料采用保守值，并把区间写成 **[88.0%, 93.5%]**
- 在局限里明确写出这一步的波动幅度
- **不在多个结果里挑好看的那个**

> 改进方向：把投票次数从 3 次提到 5 次，可以压低这个方差。

### 明确不做的（补充）

- ❌ 用人工子集同时做「调参」和「评估」—— 会过拟合，实测掉 6 个百分点
- ❌ 用主动学习样本估计准确率 —— 选择偏差，是系统性错误（见本文档第二节方法5）
