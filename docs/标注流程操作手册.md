# 标注流程操作手册

> 本文档说明「数据 → 标签」这条流程的每一步：做什么、为什么、看点是什么。
> 每一步都是一个批文件，**双击即可运行**，你可以逐步参与。

---

## 一、总体流程

```
原始数据（B站采集）
   ↓
[3] 清洗数据与规则标注     ← 去重 / 剔噪声 / 每条规则投票
   ↓
[4] 大模型标注             ← DeepSeek 打三维标签（每批落盘，可续跑）
   ↓
[5] 大模型投票             ← 低置信度样本问 3 次取多数
   ↓
[6] 聚合标注               ← 规则投票 + 大模型投票，加权合并
   ↓
[7] 生成抽检表             ← 200 随机（度量）+ 100 主动（改进）
   ↓
[8] 评估标注质量           ← 准确率 + 置信区间 + 各规则精度
   ↓
[9] 五路分析               ← 产品线 / 品牌 / 痛点 / 内容 / 场景
```

## 二、每一步在做什么

### [3] 清洗数据与规则标注

**做什么**
- 剔除无 bvid 记录、按 bvid 去重、剔除无效记录、剔除播放量 < 100 的噪声样本
- 为每条记录跑「规则层」（标注函数 LF），记录**每条规则投了什么票**

**关键概念：规则可以弃权**
按弱监督的标准定义 `λ : X → Y ∪ {-1}`，规则不是「必须判定」，
而是「有把握才投票，没把握就弃权」。所以你会看到某些规则 coverage 很低，这是正常的。

**看点**
- 清洗后剩多少条
- 各规则的 coverage（覆盖率）

---

### [4] 大模型标注

**做什么**：把每条记录的标题+标签交给 DeepSeek，输出
- `relevance`（A/B/C/N，相关性）
- `theme`（主题）
- `product_line`（产品线，仅 A 级）
- `confidence`（把握度）

**关键设计：每批落盘，可断点续跑**
每 25 条写一次 `data/clean/label_ckpt.json`。
中断后重新双击本步，会从断点继续，**不会重复花钱调 API**。

**注意**：如果本步**秒退**并显示「从检查点恢复 150/150 批」，说明之前已经跑完，属正常。

---

### [5] 大模型投票

**做什么**：对第 4 步里 **置信度 < 0.8** 的样本，再问 3 次（temperature=0.8 制造多样性），
取多数票，并用「一致率」替代模型自报的置信度。

**为什么用一致率而不是模型自报置信度**
模型自报置信度普遍**过度自信**；多次采样的**一致率**是更客观的不确定性度量。
（依据：Self-Consistency, arXiv:2203.11171）

---

### [6] 聚合标注

**做什么**：把两种投票合并成最终标签
- 规则的投票（带权重）
- 大模型的投票（作为一条高权重投票者）

**为什么用加权投票而不是完整 label model**
Snorkel 原文实测「建模优势」在部分数据集**仅 0.1%**，且理论上以 O(标签密度²) 增长。
我们只有十余条规则、4 个类别，属于**低标签密度**，加权投票即可。
（依据：arXiv:1711.10160 Example 1.1 与 Proposition 1）

**看点**
- 最终 A/B/C/N 分布
- 「低优势样本」有多少（margin < 0.15，最容易出错）

---

### [7] 生成抽检表（方案B）

**做什么**：抽两组样本给你人工核对
| 组 | 数量 | 用途 | 能否用于度量准确率 |
|---|---|---|---|
| 随机（分层） | 200 | **度量**准确率 | ✅ 可以 |
| 主动学习 | 100 | **发现错误** | ❌ 不可以 |

**为什么必须分开**
主动学习刻意挑最不确定的样本，其错误率必然偏高。
用它算准确率不是「有误差」而是**系统性错误**。

**你要做的事**
打开 `results/人工抽检_300条_方案B.csv`，
在「人工核对(填A/B/C/N)」列填入 **A / B / C / N**。

---

### [8] 评估标注质量

**做什么**
1. 用**随机组**算准确率 + Wilson 95% 置信区间
2. **实测每条规则的精度**，据此自动校准聚合权重
3. 导出错误清单，用于回补规则

**注意**：本步**只会用随机组算准确率**，主动组只作为参考打印出来。

---

### [9] 五路分析

**做什么**：产品线讨论度 / 品牌声量与口碑 / 用户痛点 / 内容策略 / 使用场景

**重要**：只有 `final_label = A`（智能硬件本体）的记录才用于**产品线结论**；
B（延伸相关）与 C（用户语境）用于需求与语境分析，**不可混用**。

## 三、常见问题

**Q：某一步秒退怎么办？**
A：看输出。例如第 4 步秒退说明已跑完（有检查点），是正常的。

**Q：中途关了窗口会怎样？**
A：第 4 步有断点续跑，不会丢；其他步骤重跑即可，不额外花钱。

**Q：CSV 打不开？**
A：CSV 用 Excel 双击即可打开；若乱码，用「数据 → 从文本导入」并选 UTF-8。

**Q：为什么抽检表里有些行没有规则判定？**
A：那表示所有规则都**弃权**了，最终标签完全来自大模型。这是允许的。

## 四、v2 流程变化（2026-10-06，全流程跑通后修订）

### 4.1 全流程现在是 10 步

```
[3] 清洗数据与规则标注
[4] 大模型标注              ← 断点续跑，每批落盘
[5] 大模型投票              ← 低置信样本自一致性投票
[6] 聚合标注                ← final_label = 大模型；agg_label = 规则层独立聚合（对照）
[4b] 抽检表合并（新增）      ← 复用人工标注，只用新流程刷新模型/规则列
[8] 评估标注质量（升级）
[9] 五路分析（改为基于 final_label）
[新] 生成运营方案报告
[新] 生成交互式看板
[新] 生成交付文档（md + docx）
```

### 4.2 新增步骤：抽检表合并（复用人工标注）

上一轮的抽检表 `results/人工抽检_300条_方案B(打分).csv` 里的人工标注是**有效资产**，
但它的「规则明细 / 大模型*」几列是旧口径。用 `src/py/step4b_merge_audit.py`
按「标题 + 播放量」把两边接起来：

- **抽样结构 + 人工标注**（一轮「人工核对」+ 二轮「人工复核」）→ 原样搬过来
- **规则层与模型层的所有字段** → 用新流程产物刷新
- 产出 `results/人工抽检_300条_方案B.csv`（**旧表一个字节都不改**）

之所以成立：人工判断只看标题+标签、与流程版本无关；且 300 条标题+播放量
在当前 4,375 条数据里 100% 精确匹配（含 2 条重名标题，用播放量可唯一区分）。

### 4.3 第 8 步（评估）升级为 5 个小节

1. **主口径准确率**：`final_label` vs 一轮人工，**只用随机 200 条** + Wilson 95%CI
2. **后分层加权估计**（稳健性检验）
3. **人工噪声分析**：一轮 vs 二轮盲判复核（自洽率 / 谁判错 / 真值区间）
4. **规则精度表**：全 300 条 + 仅随机 200 条两列（**不再自动校准权重**，原因见方法规范修订5）
5. **错误清单** → `results/抽检错误清单.csv`

### 4.4 第 9 步（分析）改为基于 `final_label`

`analyze.py` 现在读 `data/clean/labeled.jsonl`，并**按标签层过滤**后交给各模块
（每个模块用 `LEVELS` 常量声明自己用哪几层）：

| 分析 | 使用层 | 依据 |
|---|---|---|
| 01 产品线讨论度 | **仅 A** | 只有硬件本体的讨论才能代表产品线热度 |
| 02 品牌声量 | **仅 A** | 品牌竞争发生在硬件本体 |
| 03 用户痛点 | A+B+C | 产品吐槽 + 耗材/健康需求 + 用户语境，分层报告 |
| 04 内容策略 | A+B | 内容形态与时长是投放参考 |
| 05 使用场景 | A+B+C | 回答"用户是谁" |

产出 `results/01~13_*.csv` + `results/analysis.json`。
